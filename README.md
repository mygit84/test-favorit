# Подбор автозапчастей по артикулу

Клиент на React для API Favorit Parts. По артикулу приложение показывает список производителей. По выбранному производителю — деталь, её аналоги и предложения по складам.

Стек: Vite, React (JavaScript), Redux Toolkit, Bootstrap 5 (только CSS).

## Запуск

```bash
npm install
cp .env.example .env   # вписать ключ покупателя в VITE_API_KEY
npm run dev
```

Другие команды: `npm run build` — сборка, `npm run lint` — проверка кода (oxlint, идёт с текущим шаблоном Vite), `npm test` — тесты.

## Зачем прокси Vite

API работает по HTTP и не отдаёт CORS-заголовки, поэтому браузер не даст обратиться к нему напрямую со страницы. Фронт ходит на `/api/?...`, а Vite перенаправляет запрос на `http://api.favorit-parts.ru/hs/hsprice/` (см. `vite.config.js`). Прокси работает в `npm run dev` и `npm run preview` (в Vite `preview.proxy` по умолчанию берётся из `server.proxy`). Собранный `dist/` на другом сервере без своего прокси с API работать не будет.

## Обработка ошибок

Весь разбор ответа API собран в `src/api/favoritApi.js`.

- **Сеть.** Если `fetch` не выполнил запрос, показывается «Нет связи с сервером…» и кнопка «Повторить».
- **Поле `error`.** API пишет ошибку в поле `error`, иногда со статусом 403, поэтому тело ответа читается до проверки статуса. Ошибки ключа (`Invalid key client!` из документации, `Invalid access key` — так отвечает реальный API, `Empty key!`) и лимита (`Request quota exceeded!`) переводятся на русский, остальные показываются как есть.
- **HTTP.** Статус не 2xx без поля `error` даёт «Ошибка сервера: <статус>».
- **«Ничего не найдено».** API возвращает массив с одной пустой структурой; элементы без `brand` и `number` отбрасываются, и пользователь видит «По этому артикулу ничего не найдено», а не ошибку.
- **Устаревшие запросы.** Новый поиск отменяет запросы брендов и предложений, смена бренда — запрос предложений (`AbortController` через `createAsyncThunk`); отменённый запрос не меняет состояние и не показывает ошибку. Форма во время загрузки не блокируется, а повторный клик по выбранному бренду запрос не отправляет.
- **Таймаут.** Если API не ответил за 15 секунд (`REQUEST_TIMEOUT`), показывается «Сервер не ответил вовремя…» с кнопкой «Повторить».
- **Некорректные данные.** Позиция без бренда не попадает в список производителей, повторяющийся аналог выводится один раз, цена склада без значения или не числом считается отсутствующей («—», в конце списка).

## Почему цена из `warehouses[].price`

В документации API поле `price` у позиции помечено «НЕ ИСПОЛЬЗОВАТЬ»: оно оставлено для совместимости. Настоящая цена у каждого склада своя, поэтому берётся из `warehouses[].price`.

## Почему строка таблицы — складское предложение

Одна и та же деталь лежит на разных складах по разной цене и с разным остатком. Если показывать по одной строке на деталь, пришлось бы выбирать одну цену и терять остальные предложения. Позиция без складов выводится одной строкой с ценой «—» и остатком 0.

Аналоги в фактическом ответе вложены в элемент `goods` (`goods[i].analogues`). Они разворачиваются в те же строки и помечаются бейджем «аналог». Сортировка: сначала оригинал, затем аналоги, внутри — по возрастанию цены.

## Почему поиск по кнопке/Enter

Так проще. Кроме того, не уходит запрос на каждый введённый символ: у API есть лимиты запросов, а промежуточные артикулы никому не нужны.

## Почему Redux Toolkit, а не «голый» Redux

Redux Toolkit — официальный рекомендуемый способ писать на Redux. `createSlice` и `createAsyncThunk` убирают шаблонный код и дают статусы запросов и отмену из коробки. Это соответствует требованию «чем проще, тем лучше».

## Тесты

```bash
npm test   # vitest run: Vitest + React Testing Library, окружение jsdom
```

Сеть не используется, `fetch` подменяется моком. Фикстуры в `src/test/fixtures/` — урезанные реальные ответы API (артикул OC90, бренд MAHLE).

**Слой API (`src/api/favoritApi.test.js`) — основная часть.** API ведёт себя неочевидно, и ошибка в разборе ответа незаметно портит данные на экране. Главные проверки:

- «ничего не найдено» (массив с пустой структурой) — это пустой список, а не ошибка;
- цена берётся из `warehouses[].price`, позиция без складов даёт цену `null`, склад без цены — `null`, а не `NaN`;
- аналоги идут после оригиналов, внутри — по цене; дубли аналогов схлопываются, `id` строк уникальны;
- ошибки: поле `error` при HTTP 200 и 403, HTTP-ошибка без JSON, обрыв сети, таймаут; отмена остаётся `AbortError`.

**Правила состояния (`src/store/*.test.js`).** Их легко сломать при доработках, а последствия видны не сразу. Проверяется, что новый поиск и смена бренда сбрасывают старые данные, а отменённый запрос не переводит блок в `failed`; отдельный тест проходит всю цепочку отмены на настоящем store.

**Сценарии пользователя (`src/App.test.jsx`).** Проверяют, что части правильно связаны, через роли и тексты, как их видит пользователь:

- артикул → Enter → бренды по алфавиту → клик → таблица с ценой, остатком и бейджем «аналог»;
- форму можно отправить, пока бренды грузятся;
- повторный клик по выбранному бренду не тратит лимит API, а «Повторить» после ошибки загружает таблицу.

**Что сознательно не тестируется:** вёрстка и простые презентационные компоненты без логики — такие тесты ломаются при любой правке разметки и ничего не ловят.
